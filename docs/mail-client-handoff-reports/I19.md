## Findings

**Storage.** `contact.email` stays the primary address; invoices, e-invoices, mailing lists, compose suggestions,
export, import and search keep reading it and did not change. The further addresses live in `contact_email`
(`contact_id` with ON DELETE CASCADE, `email`, `position`; an index on `email`, unique on `contact_id, email`).

- Migration `0017_contact_email.sql` only creates the table and its two indexes; the generated SQL was read
  before it was committed. No data moves, so existing contacts are untouched and the table starts empty.
- `repositories/contactEmails.ts` (new): `normalizeOtherEmails` (trimmed, lower-cased, once each, never the
  primary), `saveContactEmails` and `otherEmailsByContact`. The person, company, venue and hotel repositories
  write and read through them, inside their existing synchronous transactions.
- `otherEmails` missing from an input keeps the stored addresses, so an import or an older form cannot wipe
  them. An input that makes a further address the primary removes it from the further ones.
- zod (`ContactInput.otherEmails`), the mappers (`other_emails` → `otherEmails`) and the seed carry the field.

**Form.** `ContactFormFields` has "Weitere E-Mail-Adressen" below "E-Mail": one row per address with "Als
Haupt-Adresse" (swaps it with the primary) and remove, plus "+ Adresse hinzufügen". A row must be an address
and appear once, the primary included. The pure rules sit in `forms/contactEmailFields.ts`.

**Linker.** `addressOwners` matches the primary address or any further one, then runs the same owner fan-out,
so `SHARED_ADDRESS_LIMIT` counts the records behind every address alike. Dismissed links and thread
inheritance are unchanged and have tests with a further address.

- Rescan: `addressFingerprint()` is a sha256 of every contact address, primary and further. `linkAccount`
  stores it per account under `mailLinkAddresses:<accountId>`. When it differs, the cursor goes back to 0 and
  the whole store is read again. `insertLink` skips a link that exists or was dismissed, so a rescan adds only
  the new address's mail. An account without a stored digest (one linked before this branch) keeps its
  cursor and only stores the digest, so the update does not rescan every mailbox once.
- `saveContactEmails` emits `saved` on `contactAddressEvents`; `main/index.ts` then asks `mailLinkRunner` to
  run every account. The runner is the old trigger with a `run(accountId)` beside `onEvent`: one run per
  account at a time, a request during a run gives one more pass. `mailLinkTrigger` stays as a wrapper.
- The event fires on every contact save, not only when an address changed. Such a run finds the same digest
  and continues from the cursor, so it reads nothing old. better-sqlite3 transactions are synchronous, so
  the run starts after the save is committed.
- Removing an address keeps the links it made; changing the primary address counts as a change too.

**Aliases.** A mail account has "Weitere eigene Adressen" (comma, semicolon or line separated, checked in the
dialog by `parseAliases`). Main stores them through `normalizeAliases` (lower-cased, once each, not the account's
own address, none at all stored as no list). `ownMailAddresses` adds them to the user's own, so mail to a
forwarding address is not linked to the user's contacts. This closes the open question from I15b and I17.

**Zuordnen….** The mail header has a "Zuordnen…" button (disabled without a Message-ID).
`LinkMailDialog` picks a person, company, venue, band or event by name, through the record picker that "Als
Dokument speichern" now shares (`RecordPicker.tsx`, `recordChoices.ts`, split for the react-refresh lint rule).
`mailLink.link` → `MailLinkService.linkManually` checks the record exists, strips `<>` from the Message-ID,
brings back a dismissed link as `manual`, and otherwise inserts a `manual` link once. It changes only the app's
data, so it works on a read-only account.

**Kontakt anlegen.** "Absender als Kontakt anlegen" opens `CreateContactSheet` with a new person prefilled by
`contactPrefillFromSender`: "Last, First" is swapped, quotes go, a single word is the first name, an empty name
or one that is an address gives no name. The address is lower-cased. Saving fires `saved`, so the sender's
older mail is linked by the rescan.

## Questions

- A rescan reads every account's whole store after any address change. Fine for the mailbox sizes so far; if a
  mailbox grows very large, a targeted search for just the new address would be cheaper.
- Hotels: their further addresses are stored and shown in the form, but `hotel` is not a mail link type (it was
  not before this branch either), so neither the linker nor "Zuordnen…" links mail to a hotel. Adding it would
  mean the type, the owner fan-out and an E-Mails tab on the hotel page. Wanted?
- "Zuordnen…" offers person, company, venue, band and event; contracts and invoices are linked by their own
  code.
