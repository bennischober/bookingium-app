## Findings

All five acceptance boxes are met. Each item, and what it actually was:

- **15, dead plumbing.** `pdfName` was threaded from `main/index.ts` through the window URL to `composeRequest`
  and never read anywhere: `ComposeView` names the attachment from the `presetPdfPath` basename. The whole chain is
  gone - main, preload, the type, the window. The `presetPdfPath={composeRequest?.pdfPath}` expression in the
  non-compose branch was unreachable (that branch only runs when `composeRequest` is null) and is gone too.
- **17, compose branch without `canWrite`.** Confirmed: the branch rendered `ComposeView` regardless. Main picks a
  sandbox account today, so it was not exploitable, but the renderer should not depend on that. It now requires
  `canWrite`.
- **18, subscription filtering.** The window filtered to `op-event`, so an `isDraft` or folder change arriving as a
  sync event left it showing the old derivation until a refetch. It now follows every event of its own account.
  (The other half of item 18 - `MailPage` dropping other accounts' events, and sync not invalidating `search` -
  is listed in the task list as still open; it needs a cache-design decision, not a one-line change.)
- **22, accessibility.** The "Alle Anhänge" label sat on a plain `div`, which assistive tech ignores; it has
  `role="group"` now. The reader's reply/reply-all/forward `aria-label`s were fixed in I10 already.
