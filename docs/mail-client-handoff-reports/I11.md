## Findings

**MR-22 - fixed.**

- `core/remote_images.ts` no longer uses `fetch`. It uses `http`/`https` with a `lookup` of its own: `dns.lookup`
  with `all: true`, and the connection is refused (`EADDRBLOCKED`) when any answer is loopback, private, CGNAT,
  link-local, multicast or reserved. The check sits in the connection's own lookup, so the address checked is
  the address connected to (no rebinding window between a check and a second lookup).
- `isPrivateAddress` is a `net.BlockList`. There is deliberately no `::ffff:0:0/96` rule: BlockList checks an
  IPv4-mapped address against the IPv4 rules itself, and that rule would have matched every IPv4 address.
- A literal IP host (brackets stripped) never reaches a lookup, so it is checked before each hop.
- Redirects are followed by hand, at most 5, and only to http(s).
- A declared `Content-Length` over the cap is refused before the body is read; the body is read as a stream
  under `min(maxBytesPerImage, what is left of the total budget)`.
- The per-image timer runs until `loadOne` finishes, so it covers the body; the request's `signal` tears a
  stalled response down with an error instead of letting it end short.
- `loadRemoteImages` in `core/index.ts` re-sanitizes the stored HTML and fetches only the URLs its manifest
  lists; a URL the renderer adds is ignored.
- The option `blockedAddress` (default `isPrivateAddress`) exists for tests, whose servers are on loopback.

**MR-23 - fixed.**

- `isSafeToOpen` is an allowlist (`SAFE_TO_OPEN`: documents, images, audio/video, `ics`, `vcf`, `zip`). The old
  executable list is gone.
- `open` in `mail.router.ts`: for a type not on the list, main shows a native message box with
  "Speichern unter …" and "Abbrechen", and never opens the file. `openAnyway` was removed from the router,
  the preload API and the renderer.
- The renderer sends only the part id. `attachmentName` takes the name from the worker's `getMessage`
  (`storedAttachmentName`), so a renderer cannot rename `setup.exe` to `setup.pdf`.
- `safeAttachmentName` strips bidi controls and invisible marks (U+061C, U+200B-U+200F, U+202A-U+202E,
  U+2066-U+2069, U+FEFF) before anything else.
- `markFromInternet` writes `Zone.Identifier` (ZoneId=3) on Windows. For "Öffnen" it is fail-closed: if the
  stream cannot be written, the file is not opened. For "Speichern unter" it is best-effort, because the user
  chose the place.

**MR-33 - fixed.** `storedPasswordFor(id, target)` returns the stored password only when host (trimmed,
lower case), port and user (trimmed) match. `saveMailAccount` refuses ("Passwort fehlt") an edit that changes
any of them without a new password, so a stored password cannot be carried to another host by saving first and
testing after.

**MR-34 - fixed.** `openEmail.ts` cleans the name once (`safeAttachmentName(fileName, 'Rechnung')`) and builds
the pdf, eml and txt paths with `safePathIn`, which throws when the resolved path would leave the folder.

**Design note 5 - partly.** `window.electron` (generic `ipcRenderer` on any channel) is no longer exposed; the
renderer has only `window.api`. The windows still run with `sandbox: false`; that is a larger change and not
part of this card.

**Accepted, by design:**

- An image on a name whose DNS answers include a private address is not loaded, even if the public answer
  would have worked. That is the safe side of a split-horizon name.
- A non-allowlisted attachment can still be saved and then opened by the user from Explorer. It carries the
  Mark-of-the-Web, so SmartScreen and Protected View apply.

## Tests

- `tests/mail_remote_images_guard.test.ts` (new, 10): the private classification (IPv4, IPv6, mapped), the
  loopback default for a literal and for `localhost`, a name with a mixed DNS answer (mocked), a redirect hop
  to a refused host (with a control that the hop is reachable when allowed), a redirect to `file:`, a redirect
  loop (exactly 6 requests), an endless body and a chunked body against the streaming cap, a declared length
  over the cap, and a body that stalls after the headers.
- `tests/mail_host_hardening.test.ts` (new, 3): the stored password per host, port and user; the save that
  changes the mailbox without a password; the invoice mail paths with a traversal name.
- `tests/mail_attachments.test.ts` (13): the allowlist, RTLO and other invisible characters, `safePathIn`,
  `storedAttachmentName`, and the Zone.Identifier stream (Windows only).
- `tests/mail_remote_images_wiring.test.ts`: a URL the mail does not reference is not fetched.
- The existing remote-image suites pass `blockedAddress: () => false`, since their servers are on loopback.
- `tests/e2e/mail-client.spec.ts`: the attachment test asks to open a part sent as `setup.exe` and checks that
  the stored name comes back; on Windows it reads the temp file's `Zone.Identifier` and expects `ZoneId=3`.
