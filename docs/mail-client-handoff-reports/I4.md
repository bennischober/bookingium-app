## Findings

**MR-09 - fixed.** `SyncEngine.withSelected(path, expectedValidity, fn)` is the one way to read a folder outside
its own sync. It takes the folder mutex and `getMailboxLock(path, { readOnly: true })` (EXAMINE, never SELECT),
and returns `null` without calling `fn` when UIDVALIDITY no longer matches the stored one. `flagSweep` runs
through it, so it can no longer fetch flags from whatever folder the sync connection selected last.

**MR-10 - fixed.**

- `repairMissingFiles` groups the missing rows by folder and fetches each group through `withSelected`. A
  folder whose UIDVALIDITY changed is skipped and its rows stay missing; it no longer points a row at another
  mail's file.
- It covers every account (`repairMissingFiles(limit, accountId?)`), not only the first.
- `whenIdleForMaintenance` returns `false` on timeout instead of resolving as idle. `worker.ts` then skips the
  round and logs `<what> skipped: initial sync still running`; the next round tries again.

**MR-24 - fixed.** `nextUid(selected, uids)` stores the server's UIDNEXT from SELECT (max UID + 1 only when the
server sends none) in the full sync, the validity resync and the incremental sync, which did not write `uid_next`
at all before. A folder whose newest mails were moved or deleted now matches on the next poll instead of being
fully resynced every 120 s.

**MR-25 - fixed.** A full disk (`isDiskFull`, set by `noteDiskFull(path)`) stops:

- `pollOnce` (returns `false` before any STATUS);
- IDLE (waits instead of reconnecting);
- `syncFolder` (throws the disk-full error);
- `syncAll` (returns the status before connecting);
- the repair (skips the account; a disk-full write in the middle of a run stops it and marks the engine).

**L3 - fixed.** `pollOnce` counts the folders that answered. When there were folders and none answered, it
emits an error and calls `noteError('poll')`; it does not call `noteServerContact`, so `lastSyncAt` stays where
it was. `tests/mail_sync_time.test.ts` drops the "pending on I4" header from I9 and gains the case.

**MR-31 - fixed.**

- `store.rekeyFolder` merges into a target row that already exists. Keeping UIDs (a rename, the server kept
  them): the target's copy is dropped and the moved rows win. Not keeping them: the moved folder's rows are
  dropped, because the target already holds the server's view.
- `syncFolderList` neither creates rows for paths under a journalled `folder_rename` (pending or running) nor
  marks them absent, and `syncFolder` returns early for them.
- `write_engine.lockedFolders(op)` covers both subtrees of a rename (source and target with every child), and
  `execute` holds one folder mutex per path, nested.

**Accepted, by design:**

- A rename op stuck in `pending` pauses the sync of that subtree until the op resolves (done, failed or
  discarded in the op panel). Syncing it in the meantime is exactly the race MR-31 describes.
- No deadlock risk from the nested mutexes: only the write engine takes more than one, and its ops run one
  at a time.

## Tests

New helper `tests/helpers/scriptedImap.ts`: an IMAP server on 127.0.0.1 with several folders (which may share
UIDs), SELECT vs EXAMINE, UIDVALIDITY, UIDNEXT, UID FETCH and a STATUS that can be made to fail. It logs which
folder each FETCH really ran on. It is separate from `fakeImap.ts`, which tests the write guard's endpoint and
credential wiring and stays unchanged.

`tests/mail_mailbox_selection.test.ts` (new, 13 tests) and `tests/mail_sync_time.test.ts` (+1, L3). Every
assertion below was checked by reverting the fix it covers and confirming the test fails: 21 mutations, all
killed.

| Reverted                                                      | Test that failed                                               |
| ------------------------------------------------------------- | -------------------------------------------------------------- |
| flag sweep without `withSelected`                             | takes A flags from A                                           |
| UIDVALIDITY check in `withSelected`                           | skips a folder whose UIDVALIDITY changed; leaves the row alone |
| `readOnly` lock (SELECT instead of EXAMINE)                   | restores the file from its own folder, read-only               |
| repair reading `INBOX` instead of the row's folder            | restores the file from its own folder                          |
| repair of the first account only                              | repairs every account                                          |
| gate resolving as idle on timeout                             | the maintenance gate reports a timeout                         |
| `uid_next` on the full sync / on the incremental sync (2)     | UIDNEXT is stored from SELECT                                  |
| disk full in poll / `syncFolder` / `syncAll` / IDLE (4)       | poll, syncFolder, syncAll and IDLE make no further contact     |
| disk full: repair guard / repair `break` (2)                  | stops at a full disk and does not contact the server again     |
| L3 answered-count check                                       | does not move when the server answered no folder               |
| rename: LIST upsert / absent marking / `syncFolder` guard (3) | a pending rename keeps the folder list away                    |
| write engine subtree lock                                     | holds the mutex of every folder in both subtrees               |
| re-key merge, keep UIDs / drop UIDs (2)                       | rekeyFolder merges into an existing target row                 |

The repair's disk-full test simulates the full disk with a toggled pass-through mock of `writeMessageFile`,
because the repair writes files itself and does not go through the engine's `faultWriteCode` seam.
