The first commit is the docs correction the brief asks for before the card: `AGENTS.md` and

## Findings

**MR-17 - fixed.** `tests/mail_write_guard.test.ts` closed a fake server while an imapflow client still held
its socket, so the read failed with an unhandled `ECONNRESET` and `pnpm test` exited 1 even though every
assertion passed. The clients are now logged out before a server closes. The error is gone because the sockets are
closed in the right order, not because it is swallowed: reverting the fix reproduces it.

**Section 4, `fakeImap` - fixed.** It answered `OK` to every command it did not implement and advertised
`UIDPLUS` and `MOVE` while implementing neither. It now answers `BAD` and advertises only `IMAP4rev1 AUTH=PLAIN`.
A test shows a `MOVE` gets `BAD`.
- Worth knowing: measured, imapflow `messageMove()` RESOLVES (undefined) even when the server answers `BAD`.
  A test that only checked "does not throw" would pass against a server that refused the move, so the new test
  asserts on the raw protocol, which is the only place the refusal is visible.

**Section 4, `fakeSmtp` - fixed.** It advertised `AUTH PLAIN LOGIN` and answered `250 Ok` to `AUTH LOGIN`,
so a client could "authenticate" without the server ever seeing its credentials. LOGIN is implemented as the
real 334 challenge/response, refused with wrong credentials, and dot-unstuffing was added.

**Section 4, `mail_crash_points` - fixed.** The header claimed a process kill and a fresh process, which never
happened; it now says what it does (journal an op, replay it in the same process). Test 2 requires EXACTLY one
delivery (0 used to pass), fails when Mailpit is unreachable instead of returning a pass, and counts by Message-ID
because a subject prefix collides with mails from earlier runs in the shared sandbox. Test 1 now checks that the
source copy is gone - a `COPY` would have passed the destination-only check - and removes the mail it moved.

**Section 4, `mail_sync_time` - partly fixed, deliberately.** The file is marked pending on I4 in a header note.
Review finding L3 says it "asserts that the time moves, which is exactly the wrong behaviour of L3", but L3 is
only ever NAMED in `docs/mail-client-review.md:604`; its required behaviour is written nowhere in the repo.
Writing a test for it here would mean inventing that behaviour, and it lives in `core/sync.ts`, which is I4's file.
I9 allows this explicitly ("or is marked as pending on I4 with a reason").

**Section 4, CI - fixed as far as a local run can prove.** A Windows job runs beside Ubuntu (this is a
Windows-first app), an explicit step loads better-sqlite3 under Node and names the Electron/Node ABI mismatch in one
line instead of failing deep inside the first DB suite, and a skipped sandbox suite is annotated as a GitHub
`::warning::` so a green run says what it did not prove.

**Section 4, `mail-client.spec.ts` - fixed.** The data-dependent `test.skip` (no mail with an attachment, no
band) now fails with a reason: the test creates its own attachment mail and waits for it, so a missing target means
the wait lied, and a broken demo seed is not a reason to skip. The fixed sleeps this card touches became condition
waits (`expect.poll`), except one deliberate settle window where no event exists that says "no more deliveries" - it
polls the count instead of sleeping and asserting once.

## Tests and mutation checks

Every new or changed assertion, with the fix undone and the test re-run:

| Test | Mutation | Result |
|---|---|---|
| `mail_write_guard`: two accounts, own endpoint | remove the logout-before-close loop (the old order) | unhandled `ECONNRESET` returns |
| `mail_write_guard`: advertises only what it implements | advertise `UIDPLUS MOVE` again | test fails |
| `mail_write_guard`: answers BAD for an unimplemented command | answer `OK` to unknown commands again | test fails |
| `fake_smtp`: accepts AUTH LOGIN with right credentials | remove the LOGIN implementation (back to `250 Ok`) | test fails |
| `sandbox_gate`: annotates the skip on GitHub | remove the `::warning::` line | test fails |
| `mail_crash_points`: Mailpit unreachable is a failure | point the API port at a dead port | test fails, naming the unreachable sink |
| `mail_crash_points`: source copy is gone | mutate `messageMove` to `messageCopy` | test fails, `expected 1 to be +0` |
| `mail_crash_points`: **exactly** one delivery | skip the SMTP send so 0 are delivered | test fails, `expected +0 to be 1` |

Three mutations PASSED and are recorded as not load-bearing, which is what I set out to find:

- **relaxing the delivery assertion to `<= 1`** still passes, because the send succeeds and the count is 1
  either way. The assertion is load-bearing against a 0-delivery, not against its own relaxation - the row
  above proves that, and it is the case the old `<= 1` actually let through.
- **disabling the `phase === 'sent'` branch** still passes, and **removing the Message-ID probe** still passes:
  measured, `execute()` short-circuits on the op's own `done` state before either guard runs, so a replay of a
  completed op never reaches the send at all. Those two guards protect a *crash inside* SMTP (the `unknown` path),
  which this suite does not simulate. The suite therefore proves "a completed send is not repeated", not "a send
  interrupted mid-SMTP is not repeated" - that is I1's `mail_send_state` territory. Recorded rather than claimed.

Two assertions are honest about their limits rather than proven load-bearing in isolation, and say so:
the "wrong credentials" case passes when the LOGIN implementation is removed, because the accept case fails
first and covers it; the "MAIL FROM before AUTH" case guards the server's own guard and was not mutated
separately.

## Not verified

- **The CI jobs themselves.** Nothing is pushed, so neither the Windows job nor the ABI step has run on GitHub.
  What only a CI run can prove: that `pnpm install --frozen-lockfile` leaves a better-sqlite3 that loads under Node 24 on
  both runners, and that the `::warning::` annotation shows on the run summary. The ABI step was run locally under Node
  24 and reported that the module loads.
- **The Windows runner's behaviour generally.** The local gates ran on Windows through WSL, which is the closest available,
  but a real `windows-latest` runner is a different environment (path separators in the e2e helpers, file locking).
- **Whether L3 needs an assertion at all.** See the question below.
- **The sandbox suites under `cmd.exe`.** Running vitest through `cmd.exe /c` made `mail_crash_points` SKIP
  (2 skipped) instead of run, while the same command through `npx vitest` ran it (2 passed). The gate numbers
  above are from the `cmd.exe` run, so they are the conservative ones; the sandbox suites were verified
  separately through `npx` and passed. Why the two differ was not chased - it is a harness detail, not this card -
  but it is worth knowing before trusting a "2 skipped" line on Windows.
