## Findings

**MR-13 - fixed.** `saveMailAccount` stored `input.signature` and `toDto` left it out, so the renderer read
`account.signature` and always got `undefined`: no new mail carried a signature, and opening the account form and
saving it wiped the stored one because the form had nothing to send back. `toDto` now carries it; a save that OMITS
the signature keeps the stored one, while an explicit empty string clears it - otherwise "keep when absent" would make a
signature impossible to remove.

**MR-35 - fixed.** `MailPage` and `MailWindowPage` passed `onWriteTo` and `onCompose` unconditionally, so clicking a
sender on the production account opened an editor whose autosave failed silently (`.catch(() => undefined)`) and lost the
typed text. The rule is one line - only a writable account may write - but it was written twice, in `.tsx`, where vitest
cannot reach it. It now lives in `components/mail/readingActions.ts`.

**MR-36 - fixed.** `hasArchive` is global (does an Archive folder exist at all), so the action was offered inside
Archive too. The core skips a self-move and returns no op, and the release effect only shows a hidden mail again once it
has left the list - so the rows disappeared and stayed gone until an account switch or a restart, and a mixed selection
did the same for the mails it skipped. Three pure decisions in `components/mail/archiveActions.ts`; coverage is by UID,
because an `OpSummary` carries one `uid` and no id list.

**MR-37 - fixed.** The keydown handler is on `window` and only asked `isTypingTarget`, so Entf on a confirm dialog, a
popover or a compose button moved the selected list mail to Trash, and Ctrl+N/Ctrl+R on a compose button replaced the open
editor. `shortcutBlocked()` covers dialogs, alert dialogs, menus, popovers, the compose form and an open editor.

**Low items - three fixed, the rest reported.**

Fixed: `hiddenIds` is cleared on an account switch (the set belongs to the account its rows were hidden in); `addFiles`
marks the mail edited (without it the autosave never ran, so an attachment added to an open draft was lost when the window
closed); the reader's reply/reply-all/forward icon buttons have an `aria-label` (`title` is a tooltip, not an accessible
name, so a screen reader announced them as "button").

Not fixed, each needing its own card and none a regression: reopening a draft keeps its HTML; `MailWindowPage` shows an
error instead of spinning when `getDraft` fails; the preset PDF counts against `MAX_ATTACHMENT_BYTES`; unused
`search.pdfName`; events of other accounts are dropped and sync events do not invalidate `search`; the signature is applied
once; the keyboard effect subscribes once. They are named in the task list entry so they are not lost.

## Two things the e2e caught that the unit tests could not

**A regression I introduced (fixed).** I put `[role="listbox"]` among the places the shortcuts must stay out of, but
the message list IS a listbox (`MessageList.tsx:151`). Ctrl+U/Ctrl+Q stopped working in the one place they are meant to
work, and `the mail shortcuts work from the list and leave typing alone` failed. Removed the selector, kept the real
overlays (dialog, alertdialog, menu, Radix portal, compose form), and the comment now says why it must not come back.
Commit `76d93e7`. This is the value of the e2e gate: the pure tests all passed while the feature was broken.

**A pre-existing double-send, NOT from this card.** `a mail written in the editor is saved as a draft and sent` fails
alone with "expected 1, received 2": the test presses Ctrl+Enter twice to prove the guard, and two deliveries arrive.
Attribution was measured, not guessed: the same test fails identically on `feat/mail-client` with every I10 change stashed,
and the full suite passed once and failed twice alone, so it is also timing-dependent. This is a real product bug (one mail,
two deliveries) outside I10's scope - it belongs with the send state machine (I1/I2 territory), and it is recorded in the
task list rather than fixed here.

> **Review correction (2026-10-26):** not a double send. The "2" was the Drafts count: one leftover draft on the
> sandbox plus a `draftsBefore` baseline read before the app had synced Drafts. The test now waits for the server's
> STATUS count before taking each baseline; see "Found while working" in `docs/mail-client-tasks.md`.
