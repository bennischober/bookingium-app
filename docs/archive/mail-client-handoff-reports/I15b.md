## Findings

**MR-27 - fixed.**

- **The probe is folded.** `Store.foldFtsTerm` lower-cases the word and strips its diacritics (NFD, then no combining marks), which is what `unicode61 remove_diacritics 2` stores in `fts_vocab`. `capPathologicalPrefixes` probes with it, so "Ver", "VER" and "Üb" are capped like "ver" and "ub". The MATCH expression keeps the user's word; FTS folds it itself.
- **An empty expression finds nothing.** `search` in `core/index.ts` returns no items, a total of 0 and, when asked, empty facets, when the query was not blank but every term was dropped (too short, capped, or operators only). A blank query still means "no text filter".
- **Bare operators are dropped.** `ftsEscapeUserQuery` and `capPathologicalPrefixes` both build the expression through one tidy step: operators at either end go, a run of operators keeps the last, and a leading NOT goes together with its term (searching for the term alone would invert the query). When the cap drops a term, the NOT in front of it goes too; left behind, it would negate the next term.

**MR-28 - fixed.**

- **The cursor names its store.** Every store gets a `store_generation` (a UUID in `kv`, created once). A rebuild opens a new store file, so it gets a new generation. `listHeadersSince` returns a `HeaderPage`, `{ generation, headers }`, read in the same call, and the cursor is `{ generation, id }`. When a page names another generation and the cursor is past 0, the run starts again from 0; the unique index makes re-linking harmless. `storeHasRowAt` is gone, so a deleted cursor row no longer forces a rescan.
- **Row ids are never reused (found while working).** The `messages` table has no AUTOINCREMENT, so SQLite hands out the id of a deleted newest row again, and a mail that got it sat at or below the cursor and was never linked. `insertMessage` now takes the next id from a high-water mark (`message_id_high` in `kv`, kept with the insert), so ids only grow. It is the only place that inserts into `messages`.
- **Upgrade.** A cursor stored by an earlier build is a bare number and names no store, so it is not trusted: the first run after the update starts at 0 once and links what it finds again (nothing is duplicated).
- **One transaction per batch.** `linkBatch` runs inside `db.transaction` (synchronous, as better-sqlite3 needs). A batch that throws leaves no links, and the cursor is saved only after the batch.
- **Dismissed links are not inherited.** `threadOwners` filters `dismissed = false`, so a reply no longer brings back a link the user removed.
- **Errors are logged.** The trigger moved from `main/index.ts` to `mailLinkTrigger` in `MailLinkService.ts`, which logs a failed run (`Linking mail failed:`) and still runs the pass that was asked for during it.
- **Sent by special-use.** The core adds the folder's `special_use` to a forwarded `folder-done` event, and `linkableFolder` links INBOX and the folder whose special-use is `\Sent`. A folder that is only called "Sent" (an archive subfolder, say) is no longer linked; one called "Gesendete Objekte" now is.

**Host L3 - fixed.**

- **The cap counts owners.** `addressOwners` counts the people, companies and venues behind an address, not its contacts, so one contact that stands for 21 records links nothing. A shared address on many contacts is still capped the same way.
- **Every own address.** `ownMailAddresses` takes every configured account's address, plus its login when that is an address, and `mailAddresses` drops all of them. Mail between the user's own accounts links nothing.

## Not verified

- The cost of the folded probe on the real mailbox. The cap was measured on 2026-10-23 with the unfolded probe, which never fired on capitalised words, so the canary is the first run where it caps them; the 20,000-entry limit is unchanged.

## Limitations

- "The user's own aliases" are the configured accounts' addresses and address-shaped logins. The account settings hold no list of aliases, so an alias that is not an account of its own (a forwarding address, say) is still linked like anyone else's. A field for aliases would need a schema and dialog change.
